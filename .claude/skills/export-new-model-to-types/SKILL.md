# Exporting a new Pydantic model to the type packages

The type packages are generated from Pydantic models declared in `services/bridge/bridge_models.py`. To expose a new model:

## The one required step

Add the **exported name** (as a string) to `SCHEMA_MODELS` in `schema_gen.py`, under the correct key. `SCHEMA_MODELS` is typed `dict[str, list[str]]`; `schema_gen.py` resolves each name via `getattr(module, name)` at generation time — so paste the symbol's name in quotes, not the symbol itself.

```python
SCHEMA_MODELS: dict[str, list[str]] = {
    "bridge_models": [
        "PlaceOrderPayload",
        "PlaceOrderResponse",
        "HealthResponse",
        "ListTradesResponse",
        "WsEnvelope",
        # "NewModel",  # ← add here
    ],
}
```

The example reflects the current contents of `schema_gen.py:SCHEMA_MODELS`. Re-check the file before editing — the list changes as models are added or removed.

Then run:

```bash
make types
```

This regenerates:
- `types/typescript/http/types.d.ts` (via `schema_gen.py` → `json-schema-to-typescript`)
- `types/typescript/http/index.d.ts` (auto barrel via `gen_ts_barrels.py`)
- `types/python/ibkr_bridge_types/models.py` (via `gen_python_types.py`)
- `types/python/ibkr_bridge_types/__init__.py` (auto-AST-walked barrel)

## Choosing the right key

There is currently **one key**: `"bridge_models"`, mapping to `services/bridge/bridge_models.py` and the `IbkrBridgeHttp` TypeScript namespace.

If your model belongs to a future shared namespace (`IbkrBridge`), see the `services/shared/` instructions for the full multi-step procedure to add a new key — it requires updating `schema_gen.py`, `gen_ts_barrels.py`, `gen_python_types.py`, the top-level barrel `types/typescript/index.d.ts`, and `types/typescript/package.json` `files:` together.

## Supported symbols

Each string name in `SCHEMA_MODELS` must resolve via `getattr(module, name)` to one of these (Pydantic's `TypeAdapter` handles all three):

- **`BaseModel` subclasses** — generated as `interface Foo` in TS, `class Foo(BaseModel)` in Python.
- **Discriminated-union `TypeAlias` values** — `WsEnvelope = Annotated[WsStatusEnvelope | WsFillEnvelope, Field(discriminator="type")]`. The TypeAlias must be defined at module top level so `getattr` finds it.
- **Class aliases** — `Foo = SomeBaseModel` produces `export type Foo = SomeBaseModel` in TypeScript via an `allOf: [$ref]` schema entry.

In all three cases you only paste the **name** (e.g. `"WsEnvelope"`) into `SCHEMA_MODELS` — the symbol itself stays in its source module.

## Pydantic config that propagates

- **`ConfigDict(extra="forbid")`** → `additionalProperties: false` in JSON Schema → strict TS types (no `[k: string]: unknown`). **Always use this on external-contract models** (HTTP request/response, WS envelopes).
- **No defaults on always-populated fields** — a default makes the field optional in JSON Schema → optional in TS (`fillCount?: number`).
- **`Field(default_factory=list)`** for mutable defaults, only when genuinely optional. Never bare `[]` or `{}`.

## Things that are NOT required

- ❌ No need to edit `types/typescript/http/index.d.ts` — auto-generated by `gen_ts_barrels.py`.
- ❌ No need to edit `types/python/ibkr_bridge_types/__init__.py` — auto-generated by AST walk.
- ❌ No need to edit `types/typescript/index.d.ts` unless you're adding a brand-new top-level namespace (rare; only when `services/shared/` gains its first model).
- ❌ No need to update `types/typescript/package.json` `files:` for new symbols within an existing namespace — only when adding a new namespace directory.

## Verification

After `make types`:

1. `git diff types/typescript/` should show the new type in `http/types.d.ts` and re-exported from `http/index.d.ts`.
2. `git diff types/python/ibkr_bridge_types/` should show the new class in `models.py` and re-exported from `__init__.py`.
3. `make typecheck` (which runs `tsc --noEmit` on `types/typescript/`) should pass.

If `make typecheck` fails, the most common cause is a removed/renamed export still referenced by the hand-maintained `types/typescript/index.d.ts`. Fix the barrel.
